# W21 — Strategy API trading

## Delivered

- Added immutable `api-submit` Proposals for `open`, `close`, `resize`, and
  `cancel`. Staging stores the exact Strategy API route and JSON body. It also
  stores a proposal-bound `p-N:<uuid>` idempotency key before any send.
- Selected API submission only when an owner key exists and its known venue
  grant covers the request. Missing keys and known scope gaps keep the existing
  wallet Proposal and print the reason.
- Added `mob submit <id>` with a durable `.submission-used` marker. A send can
  never be retried through the Proposal, including after an HTTP failure.
- Added authenticated Strategy API status reads. List reads use keyset pages of
  20. Single-task reads use the task route. JSON output identifies `source` as
  `api` or `hosted`.
- Added `policy=auto`, its setup guard, home warning, and sign-guard rules.
  Manual submit needs the exact Proposal id in the latest human message. Auto
  permits only `api-submit`; it continues to block `mob sign`.
- Kept `protect`, `auto-close`, `neutralize`, and `size-mismatch-close`
  wallet-signed. Their cards explain that API-key support is not available yet.
- Added `strategy_api_base`, defaulting to `https://api.mob.exchange`. Key
  verification and Strategy API traffic use this setting.

No external runtime dependency was added. The CLI only gained the existing
workspace package `@mstack/mobius-api`.

## Submission check order

`mob submit <id>` checks in this order:

1. The Proposal exists.
2. The Proposal is not terminal, used, or expired.
3. The policy permits submission. `locked` refuses; `manual` and `auto` proceed.
4. A key is available from `MOBIUS_API_KEY` or the configured key store.
5. The durable `.submission-used` marker is written.
6. The saved route, body, and `Idempotency-Key` are sent.

The sign-guard is a separate command boundary. Under `manual`, it also requires
the latest human message to name the exact Proposal id. Under `auto`, it reads
and validates the Proposal before allowing `mob submit`.

## Exact submission output and error mapping

| Result | Output line |
| --- | --- |
| 202 accepted | `p-N: accepted, not executed; \`mob status\` shows the worker state (task <taskId>, status <status>).` |
| Missing key | `mob: no key: run mob onboard` |
| 401 | `mob: key rejected; run \`mob keys show\`` |
| 403 | `mob: <exact server message>` |
| 409 with task id | `Idempotency conflict; current task <taskId> is <status>.` |
| 409 without task id | `mob: <exact server message>` |
| 429 with Retry-After | `mob: rate limited; Retry-After: <seconds> seconds` |
| 429 without Retry-After | `mob: rate limited; Retry-After: not provided seconds` |
| Locked policy | `mob: Policy is locked` |
| Expired Proposal | `mob: Proposal expired; stage a new Proposal` |
| Terminal or used Proposal | `mob: Proposal is terminal or already used` |
| Wallet Proposal | `mob: Proposal is not an API submission` |
| Missing preview | `mob: Run mob preview before submission` |

Other network and 5xx failures keep the redacted `StrategyApiUnavailable`
message from `@mstack/mobius-api`. They also consume the Proposal marker.

The exact auto-policy setup warning is:

```text
Warning: policy auto lets the agent submit API-key Proposals inside the key's venue and size caps.
```

The active home row is:

```text
policy: auto · the agent may submit inside the key's caps
```
