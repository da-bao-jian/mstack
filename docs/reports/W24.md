# W24 — the home screen greets every entry point

Built on `main` at version 0.4.0. The version and tag were not changed. No runtime dependency was added.

## Delivered

- `@mstack/brand` now owns terminal mode selection and marked logo blocks through `renderTerminalLogo`. Normal non-TTY output is ASCII between `<<<MOB` and `MOB>>>`. TTY truecolor, 256-color and shaded mono remain unchanged. Explicit `--plain` and `--ascii` modes still override automatic selection.
- `mob`, `mob hello`, the `mob onboard` Ready screen and the skill splash all use that renderer. Headless full home screens stack the marked logo before the information rows.
- Every skill uses the shared splash. The first skill in an hour greets once per configured owner, or once per `MOB_HOME` when no owner exists. The router always greets. Directory locks suppress concurrent duplicate greetings.
- All 20 generated Claude and Codex `SKILL.md` files carry the exact verbatim-block rule. `/mob-setup` also requires the Ready home block at the top of its reply. The largest generated skill is 44 lines, below the 120-line limit.
- Every path in `docs/AGENT-INSTALL.md` runs bare `mob` after verification and requires the agent to reproduce its output. The canonical paste prompt remains five lines across the prompt doc, README and Mobius ask. The landing-page copy includes the marked ASCII logo.
- The paste-prompt and Journey E smokes now require the marked logo. The paste-prompt fixture accepts both a release tag and the pre-release `<tag>` placeholder when it redirects the install URL to its local server.

## W24.1 — neofetch-style home screen in brand colors

Built as a follow-up on `main` at version 0.4.0. The version and tag were not changed. No runtime dependency was added.

### Delivered

- The default home uses the 13-row MoB art beside a market-first status column. Terminals below 72 columns and `--stacked` put the column below the art. `--big` retains the 25-row art.
- Truecolor and 256-color terminals use the logo palette per cell. Labels, header, underline, health marks and the three labeled swatches use the requested brand colors. Mono, `NO_COLOR` and ASCII remain plain. ASCII encloses the complete greeting in the `<<<MOB` markers.
- Each greeting runs all seven funding adapters in parallel with a five-second budget. It shows unique executable top pairs, aggregate executable-venue trending markets, optional ticker price change, and live venue coverage. A successful view is cached in `MOB_HOME`; failed live reads fall back to the cache, and `--offline` reads only that cache.
- The funding rows now preserve optional 24-hour price change from the Hyperliquid, Binance/Aster, Bybit and OKX payloads already fetched by their adapters.
- The account column shows running positions only when a key and running tasks exist. It otherwise limits standing to Ready or Onboarding, policy and one derived next action. `mob doctor` keeps the detailed configuration and health checks.
- `mob onboard` reproduces the live marked home screen on Ready and carries its known bound venues into the Ready row. The shared skill preamble continues to call `mob hello --compact --ascii`, which now renders this same live greeting.
- `mob --json` now includes `market.topPairs`, `market.trending` and `market.freshness`.

- Brand and funding normalization: `packages/brand/src/index.ts` and the funding types, validators, snapshot code and four ticker adapters.
- Tests and smokes: home market tests, three 80-column snapshots, brand and adapter fixtures, `smoke:home`, `smoke:journey-e`, and `smoke:paste-prompt`.
