## Behavior

Scan defaults to USD 1,000 and 15 rows. It sorts qualifying executable pairs first, then other qualifying pairs, then annualized spread. It selects the first pair per base after that sort unless `--all-pairs` is present. Filters apply before the top limit. JSON retains the full ranked result and adds `view`.

Rates preserves raw native rows and adds a filtered view with hourly rates. Human data output always includes age, source, simple annualization, venue errors, and unmatched count. JSON stays on stdout; its human footer goes to stderr.

Exit codes are 0 success, 1 usage/config/request error, 2 no venue rates, and 3 partial snapshot/history failure under `--strict`. Exit 2 takes precedence when no rates exist. Empty filtered views still exit 0 when the snapshot is healthy.

History resolves all current USD-stable native listings for the requested base. It reports each listing's sample count, measured hours, average/min/max hourly rates, and simple annualization. The average is total interval funding divided by total measured hours. Its best pair uses distinct venues and reports a gross average spread. Lighter's missing keyless history and unresolved listings are explicit.

HL settlement rates use one-hour intervals. Other venues derive each interval from consecutive settlements. Binance/Aster fetch one day before the requested window to find the boundary; no predecessor causes an explicit error. Bybit requests a preceding settlement separately. OKX pages backward with `after` and uses `realizedRate`. Duplicate rows, stalled cursors, invalid values, and HTTP failures throw; no current rate substitutes for history.

An initial live check exposed Aster's end-time-only behavior: it returned an old listing settlement, inflating coverage. The final reader supplies both time bounds and uses the nearest predecessor from the bounded context. Regression tests require that request shape. The final live history reports 72 hours for every BTC listing.

Status renders all **40 field names** in the pinned `publicTask` projection. Funding accrued is labeled an estimate. Trim and resize logs paginate to completion. Every Mobius request sends both required client headers. Malformed and non-2xx bodies fail with HTTP status and a bounded excerpt.

$ mob explain funding
# Funding

## Simple

Funding is a payment between traders who hold opposite sides of a perpetual contract. When the rate is positive, longs pay shorts. When it is negative, shorts pay longs. A pair can earn the difference by holding the lower-rate market long and the higher-rate market short. Rates change, so a current quote is not promised income.

## Precise

For an interval rate `r` over `h` hours, `rate1h = r / h`. For equal base exposure, the quoted hourly funding spread is `shortRate1h - longRate1h`. Positive funding credits the short and debits the long. Historical average hourly funding is `sum(interval rates) / sum(interval hours)`, not an unweighted mean when intervals differ. The scanner's annualization is simple: `rate1h × 24 × 365 × 100` percent. Actual cash funding also depends on the venue's settlement notional and position size. Fees, basis changes, and unequal exposure affect net results. Lighter's current feed reports an eight-hour equivalent, even though settlement is hourly.

Sources: `docs/PRD.md` §4 and §7.4; `reference/upstream/tg-monitor/README.md`.

## Decisions, limits, and open questions

- JSON footers use stderr so stdout remains parseable JSON. Both streams contain the specified information.
- History compares all USD-stable native listings found for the base, consistent with the default ranking scope. It does not silently pick one quote market per venue.
- Historical retention and gaps can limit coverage. The reported hours are measured settlement intervals, including timestamp jitter. Binance/Aster require a predecessor in the extra day; a new or sparse listing can fail explicitly. No assumed eight-hour interval is used for history.
- Knowledge files distinguish the P0 scanner from the existing server and the separate leveraged vault. The bundled reference lacks complete worker timing and confirmation logic; the knowledge base says so rather than inventing it.
- Fee defaults remain estimates. Mark prices do not measure executable depth. Status leverage/margin metadata does not prove live venue settings. Funding accrued remains an estimate.
- There are no blocking questions. The only live status evidence is the empty dummy-owner list described above.
