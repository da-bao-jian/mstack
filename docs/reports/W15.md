# W15 — Sign page, ceremonies, and non-interactive setup

Built on `w15`, based on `1c87dc3`. One delivery commit: `feat(ux): brand sign page, ceremony steps, non-interactive setup`. No push or changes to `main`.

## What was built

- `packages/signers/src/browser.html`: one self-contained page with the cream background, near-black text, brand accents, system dark mode, and the MoB logo. The inline 44-wide grid draws one SVG rect per opaque pixel at 4 CSS pixels per pixel. A test compares every rect with `assets/logo.json`. The wordmark sits beside the logo.
- The page puts purpose, scope, account comparison, wallet picker, exact message, digest, expiry, and actions in the requested order. Wallet choices use native buttons, embedded provider icons, and text-only names. The message has a Copy button and a keyboard-accessible scroll region. Focus is visible. Addresses, messages, and digests wrap at phone widths.
- `packages/signers/src/browser.ts`: CSP adds only `img-src data:` for embedded wallet icons. Script and style nonces, token/Host/Origin checks, recovery, single-use behavior, expiry, and server shutdown remain in place. Remote icons are ignored. SVG icons remain image content; they are never inserted as page markup.
- `apps/cli/src/{p1,wallet-wait,run}.ts`: browser and WalletConnect signing print the URL once. TTY output includes the preview, optional WalletConnect QR, fallback hint, and one countdown line refreshed every two seconds. The line clears before submission or an error, and its timer stops on every exit. Non-TTY signing prints only the URL and final result. Successful results retain the server answer and the distinction between submission and execution.
- `apps/cli/src/{bind-ceremony,bind-command,onboarding-stage}.ts`: three-step headers and lists precede binding previews, including reuse of pending Proposals. Each preview explains the signature and the next effect. Hyperliquid uses prepare / approve agent / approve builder fee. Aster and Robinhood Lighter use confirmation as their third step; Lighter mainnet uses integrator approval. Hyperliquid agent approval without a builder uses confirmation. Existing submission bodies, polling, key-capability text, and stop lines remain intact.
- `apps/cli/src/setup-command.ts`: public setup flags, numbered interactive prompts, optional legal skip, and WalletConnect project-ID collection. All values are validated before config writes. Setup never creates or unlocks a keystore.
- `skills-src/mob-setup.md.tmpl` and generated `skills/mob-setup/SKILL.md` / `skills-codex/mob-setup/SKILL.md`: pass confirmed public choices as flags, without piping answers. Existing per-Proposal authorization rules remain intact.
- Tests in `packages/signers/test/{browser-page,browser}.test.ts`, `apps/cli/test/{onboarding,browser,walletconnect}.test.ts`, their browser/WalletConnect fixtures, and `packages/skills.test.ts` cover the new UI states and CLI behavior. CLI tests remain included through the existing root test bridge.
- `README.md`: an additive section delimited by `BEGIN/END W15 SIGNING AND SETUP`. `assets/logo.json` received whitespace-only formatting because its baseline failed the root lint gate. Parsed JSON is identical to the starting commit.

No dependencies were added. Dependencies were absent in this new worktree, so `bun install --frozen-lockfile` installed the existing 402 packages. `bun.lock` and all manifests remain unchanged.

## Page text rendering

Common layout:

```text
[MoB pixel logo] mstack
REVIEW SIGNATURE · P-1
This signature authorizes: <purpose>
It cannot move funds.

Expected owner
<owner address>
Connected account
<account address or Not connected>
<account check>

Choose your wallet
[provider icon + provider name] ...
[Connect wallet]

Exact message                         [Copy]
<exact UTF-8 message or formatted typed data JSON>

Digest
compare with your terminal
<digest>

Expires in 4:12
[expiry progress bar]
[Sign in wallet] [Reject]
<state copy>
```

| State | Copy |
|---|---|
| Loading | `Loading Proposal…` |
| Ready to connect | `Connect your wallet to review this Proposal.` |
| Connecting | `Connecting. Choose the expected owner in your wallet.` |
| Owner match, green | `✓ Account matches the expected owner.` |
| Owner mismatch, red | `Account mismatch. Signing is disabled.` and `Connected account does not match the expected owner.` |
| Connected | `Connected. Review the message and digest before signing.` |
| Chain switch | `Chain switch needed. Switch to BNB Smart Chain Testnet in your wallet.` |
| Refused chain switch | The chain-switch sentence followed by the wallet's error text; signing stays disabled. |
| Waiting for wallet | `Waiting for wallet. Review and approve the signature in your wallet.` |
| Accepted | `Done. You can close this tab.` |
| Reject button | `Rejected. No signature was submitted.` |
| Wallet rejection | `Rejected in wallet. No signature was submitted.` |
| Expired | `Expired. Return to your terminal to stage a new Proposal.` and `Proposal expired` above an empty bar. |
| Error | `Error. <reason>`; for example, `Error. Invalid token` or `Error. Wallet disconnected`. |
| No provider | `Error. No wallet found. Enable a wallet extension and reload.` |
| Copy success | `Copied exact message.` |
| Copy failure | `Copy failed. Select the exact message and copy it manually.` |
| Connection-only binding check | Heading: `This connection checks: <purpose>`. Completion: `Wallet chain received. Return to your terminal. No signature requested.` The sign button is hidden. |

Known signing chains use Ethereum, BNB Smart Chain, BNB Smart Chain Testnet, or Arbitrum One names. Other configured chain IDs display as `chain <id>`.

Expiry or rejection during a wallet request prevents a late signature POST. Completed states survive later clock ticks and account events. Reject is disabled once the signature is being verified, so the page cannot claim cancellation of an accepted signature. The page's acceptance state refers to the signature; the terminal reports the subsequent submission result.

## CLI output samples

These samples abbreviate addresses, tokens, and large Proposal payloads. They show the new output shape.

```text
$ mob setup --owner 0x… --signer browser --policy manual --no-legal
Setup saved. No keystore was created.
Legal acceptance skipped (--no-legal).

$ mob setup < /dev/null
mob: Non-interactive setup requires: --owner, --signer, --policy
# exit 1
```

Required non-interactive flags are owner, signer, and policy, even when those settings already exist. Optional auth base and legal chain use saved values, or the existing defaults. WalletConnect also needs a supplied or saved public project ID. Complete flags suppress prompts on a TTY too. Legal acceptance still stages and stops unless explicitly skipped, already current, locked, or unavailable under the existing 503 handling.

Interactive prompts use these labels. A missing owner or signer shows `[required]`; otherwise the saved/default value appears in brackets:

```text
Setup · 1 of 5 · Owner [required]:
Setup · 2 of 5 · Signer (keystore | browser | walletconnect) [required]:
Setup · 3 of 5 · Policy (manual | locked) [manual]:
Setup · 4 of 5 · Auth API base [https://auth.mob.exchange]:
Setup · 5 of 5 · Legal signing chain id [97]:
```

WalletConnect adds `Setup · 2 of 5 · WalletConnect project ID [required]:` within the signer step.

```text
$ mob bind hl
Hyperliquid binding · step 2 of 3 · approve agent
✓ prepare binding
▶ approve agent
· approve builder fee
This signature approves the venue key and its capabilities shown in the Proposal.
After submission, run mob bind hl to check the next step.
The Mobius server creates and holds this venue key.
p-3
Status: awaiting-signature
Purpose: hl: approve-agent; key can trade, cancel and adjust margin; cannot withdraw; expires after 179 days
Owner: <owner>
Route: POST https://api.hyperliquid.xyz/exchange
Expires: <deadline>
Message:
<stored typed data>
Digest: <digest>
Stored body: <stored body>
Submit plan: <stored submit plan>
Preflight: <checks>
Stopped before signing. To authorize, name p-3 and run mob sign p-3.
```

TTY wallet wait, after the Proposal preview:

```text
http://127.0.0.1:<port>/sign/p-1?t=<token>
If no page opened, paste the URL into your wallet browser
Waiting for your wallet · expires in 4:12
```

The wait line updates in place every two seconds. It clears before the final line. WalletConnect prints its pairing URI once and a QR before the same hint/countdown. Non-TTY output is only:

```text
http://127.0.0.1:<port>/sign/p-1?t=<token>
p-1: submitted · Server answer: {"taskId":"fake-w7-1"} · Submission is acknowledged; execution is not confirmed.
```

For WalletConnect the first line is its `wc:…` URI. Failure returns the URL, if already available, followed by the existing one-line `mob: <reason>` error on stderr.

## Open questions and deliberate limits

No blocking questions. No live legal acceptance, venue binding, trading request, or WalletConnect relay session was performed. Real wallet approval remains a human smoke check. Light mode is covered by source assertions; manual Chrome inspection used dark mode.

Remote or malformed provider icons are omitted to retain the no-external-resources requirement. Legacy `window.ethereum` discovery has no `info.icon`, so it shows the Browser wallet label. No new signing API, network fallback, daemon, telemetry, secret input, or dependency was added.

The earlier README setup-menu wording is superseded by the delimited W15 section. Other README sections and the changelog were left for the parallel packages. `reference/`, `docs/PRD.md`, other delivery reports, and the pre-existing untracked `docs/prompts/W15.md` were not changed.
