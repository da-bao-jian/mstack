## Built

- `packages/liquidation/`: `@mstack/liquidation`, with verbatim `index.ts`, `distance.ts`, and `trim.ts` from `mobius@33ed2ece`. Each file has its provenance header. Whole-file SHA-256 tests exclude only that added header. Tests retain the applicable frontend `deltaNeutralMath.test.ts` cases and the upstream liquidation trim suite, plus hand-computed examples.
- `packages/funding/src/metadata/index.ts`: strict reads for HL core/HIP-3 `meta`, both Lighter deployments' `orderBookDetails`, and Aster `exchangeInfo`. Native market names remain unchanged. Metadata includes lot sizes, base/notional floors, precision, and published leverage/margin data. Lighter fractions use the venue's 10,000-unit scale. Inactive Lighter markets have no executable metadata; they are not given a guessed precision or margin fraction.
- `apps/cli/src/preflight/{checks,readiness,open,manage}.ts`: named checks with an explanatory first failure. Config, credentials, rebind checks, HL open-interest caps, marks, metadata, coarser-lot quantities, floors, entry spread, protection, task existence, owner, status, and resize rules are checked before staging. These functions use injected reads and clocks; they do not access a key or write a Proposal.
- `apps/cli/src/preflight/resizePlan.ts`: verbatim upstream source through `planResize`, with a provenance header and a pinned digest. Resize targets round toward the current size; checks reject no change, below-floor orders, and uncloseable remainders. Non-power-of-ten Aster lots also retain their published step.
- `apps/cli/src/positions.ts`, `run.ts`, and `commands/status.ts`: `open`, all six manage commands, and `status --readiness`. An open accepts native `venue:market` strings, fixes both marks at staging, and calls the existing byte-exact `stageOpenBody`. Every successful mutation command prints its preview and the explicit stop instruction. A failed preflight creates no Proposal. No leverage or margin-mode segment is added to a message.
- `packages/proposals/src/{model,preflight}.ts`: named immutable staging evidence and minimum-remaining-lifetime read assertions. The intent hash covers the stored plan. CLI preview rechecks current config, retains staged math/metadata, and reruns credential/task assertions, including resize's current-size assertions. Signing still submits only the stored body plus its signature. The existing owner recovery, durable one-attempt marker, and expiry checks are unchanged.
- `packages/mobius-client/src/binding.ts`: the public Lighter `integratorApprovalExpiresAt` metadata field. Mainnet approval must be true and its expiry must be strictly more than 24 hours away. `client.ts` now preserves the raw readiness error body, including its whitespace, when reporting a server refusal.

## Open questions and limits

1. **Aster recording is incomplete.** A direct `curl --max-time 20 --fail --silent --show-error https://fapi.asterdex.com/fapi/v3/exchangeInfo` request timed out with curl exit 28 after 20,005 ms. `exchangeInfo.synthetic.json` is explicitly labeled synthetic, not recorded. HL metadata tests project the meta object from existing recorded `metaAndAssetCtxs` responses; Lighter reuses the existing recorded details. Record and verify Aster's real metadata when connectivity returns. No synthetic data is used by production code.
2. **Protected Aster opens fail closed.** The assigned keyless `exchangeInfo` read has no maximum-leverage/maintenance-margin ladder. The upstream frontend reads a separate notional-dependent Aster ladder. W10 does not invent a maintenance fraction or treat an unknown distance as safe. Unprotected Aster opens can stage; managing protection on an existing running task uses the existing server route. Is a separate Aster ladder read wanted in a later package?
3. **The rebind check is intentionally literal.** The real server returns 409 when an active strategy uses that venue. Following the assignment, this blocks another open during preflight and is also shown by `status --readiness`. It does not mean the existing task's key is invalid. Confirm whether later work should separate binding readiness from permission to rebind.
4. **The supplied reference has no resize-planner test file.** `frontend/test/features/delta-neutral/` contains `resizeTaskMessage.test.ts`, but no tests of `planResize` or the quantizers. Existing byte-exact message tests still run. New planner tests pin the upstream source comments' BTC precision example, `12.347` rounding examples, the float guard, coarser linked lots, and unknown-precision refusal. No missing test was represented as an upstream case.
5. **Protection is an assumption-based estimate.** The preview says “assumed leverage, not verified on the venue.” It uses the ported isolated-position estimate with published maintenance data, assumes the position's own margin, and excludes other account positions. No leverage or margin mode is set. Missing protection is off, so no unverified default threshold is signed.
6. **Execution remains the server's final gate.** The create wire body carries USD size and fixed marks; quantized quantities are preview evidence, not new wire fields. The server/worker may refuse or recalculate execution from its own current reads. Manage requests have no nonce and remain replayable during the server's 300-second window, even though each local Proposal expires at 300 seconds and permits one signing attempt.
