# W4 — P0 skills, plugin, setup

## Built

- Four original skill templates in skills-src/: mob, mob-scan, mob-explain, mob-status. Host overlays live in hosts/claude/ and hosts/codex/. scripts/gen-skill-docs.ts renders eight committed SKILL.md files under skills/ and skills-codex/.
- scripts/skill-preamble.sh supplies binary discovery, version/config, one status-only API request, owner presence, read-only policy, and hourly-throttled origin update checks. Failed update checks do not use cached upgrade results. Every Mobius health request sends the client and User-Agent headers.
- Claude frontmatter allows Bash, Read, and AskUserQuestion. Codex has only name/description and normal prose questions. Skills preserve user-supplied sizes, treat returned text as data, refuse P1 actions, and never execute mobOpen output.
- .claude-plugin/plugin.json and marketplace.json declare mobstack 0.1.0, MIT, the skill directory, and api_base configuration. bin/mob is a POSIX shim that uses the compiled binary or builds with Bun once when missing. Build logs use stderr.
- setup and scripts/setup.ts build the CLI, install host-specific skill links, and print the host integration paragraph. auto selects all detected host directories; no detected host requires an explicit choice. Ownership ledgers under ~/.mob record only newly created links. Uninstall preserves user replacements, config, pre-existing links, and directories.
- apps/cli/src/upgrade.ts and CLI wiring add mob upgrade: origin discovery, fast-forward-only pull, frozen install, build. A standalone binary or plugin cache without Git metadata reports no remote configured. There are no retries, new remotes, or signing commands.
- README now contains both install paths, the six P0 commands, skills and maintenance instructions. The intended lu-bann/mobstack repository is marked not published yet. The custody statement is unchanged.
- Root knip includes scripts and the setup entry. CI regenerates both host outputs and runs git diff --exit-code. scripts/live-skills.ts provides the guarded live smoke.

I studied ~/.claude/skills/gstack/SKILL.md.tmpl, scripts/gen-skill-docs.ts, hosts/claude.ts, hosts/codex.ts, setup, and bin/gstack-config before building W4. This implementation uses its template/overlay/generation, shell preamble, shim, and host installation mechanics. No gstack code was copied.

## Decisions and limits

- The runtime bin link is ~/.<host>/skills/mobstack/bin, separate from the four skill links. This gives the exact requested binary lookup path without exposing the other hosts skill tree as another installed skill.
- In Claude Code, CLAUDE_PLUGIN_ROOT/bin is appended to PATH before normal binary discovery. This enables the packaged shim without requiring a prior global setup. An existing mob on PATH retains priority.
- The manifest declares api_base with the requested default. CLI config is authoritative for skill reads; README tells users how to apply a custom choice with mob config set api_base. No undocumented host config injection is assumed.
- The marketplace and plugin manifests passed local validation. An interactive plugin installation and published GitHub marketplace were not exercised. No origin was created, so real remote fetching/pulling was not tested; fixture command tests cover those paths.
- A failed or pending update check remains explicit and throttled until the next hour. No stale upgrade result is printed. Upgrade availability reports the local and origin/main commit hashes; it does not auto-update.
- No external dependency was added. Knowledge files from W3 are reused without changes. No blocking open questions.

## Deliberately left out

No W5/MCP work, mutation skills, signing or wallet code, credentials, telemetry, marketplace publication, remotes, or pushes. reference/ and docs/PRD.md are unchanged. The three unrelated docs/prompts/ files remain untouched and untracked.
