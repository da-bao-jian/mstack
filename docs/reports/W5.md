# W5 — read-only MCP server

Built on 2026-10-10, after fix commit `243cfdd` (`fix(skills,cli): preamble resilience, net APY ranking`). The W3.2 and W4.1 evidence is appended to their package reports.

## What changed

- `apps/cli/src/commands/{scan,rates,history,explain,status,config}.ts` now hold the six shared async command functions. They accept typed options and a Runtime containing fetch, clock, and config home. They return data without printing. `run.ts` parses arguments and renders those results. `scan-view.ts` and `render-history.ts` separate selection and rendering. CLI JSON shapes, defaults, footers, and exit codes remain unchanged by W5.
- `apps/cli/src/mcp.ts` serves stdio in the existing binary through `mob mcp`. `mcp-tools.ts` defines seven read-only tools and validates their JSON inputs. Command errors return `isError: true` with the CLI's `mob:` message. Partial venue failures remain visible in the result's `failed` array.
- Every call has a 60-second deadline, with cancellation propagated to outstanding fetches. Snapshot reads retain the CLI's 30-second timeout. The deadline also covers history pagination and status log pagination.
- `.mcp.json` registers `${CLAUDE_PLUGIN_ROOT}/bin/mob mcp` for the plugin. Root and CLI READMEs document separate Claude Code registration and the JSON settings for Cursor, Claude Desktop, and Windsurf.
- `apps/cli/test/mcp.test.ts` uses SDK `InMemoryTransport`. `test/fixtures/mcp-tools.json` pins the complete tools/list response, including names, descriptions, schemas, and annotations. An explicit JSON snapshot avoids duplicate Bun snapshots when tests run through the root bridge.
- `apps/cli/scripts/live-mcp.ts` and root `live:mcp` run the compiled binary through the SDK stdio client. The script requires `MOB_LIVE=1`, uses an empty temporary config home, and prints the selected views from the full scan response.

All tool descriptions end with: “Read-only. This tool never signs, trades, or holds keys.” There is no configuration write, signing, trading, shell, or upgrade tool. Task owners fall back to the public `owner` config key; missing owners name `mob config set owner` in the tool error.

The SDK response contains one text block: JSON for command objects, Markdown for explanations, or the config value. Full scan results are not duplicated in a second structured content block. Private non-enumerable metadata preserves CLI exit-code and footer information without adding fields to the public JSON.

## Dependency

Pinned `@modelcontextprotocol/sdk` to **1.32.1** in `apps/cli/package.json` and `bun.lock`. It is the first and only external direct runtime dependency. Workspace library dependencies remain `workspace:*`; SDK transitive dependencies are locked too.

The SDK provides protocol negotiation, validation, stdio framing, cancellation, client transports, and the required in-memory transport. The implementation uses its low-level Server API and JSON Schema validator to share domain validation with CLI commands. No second direct schema dependency is needed. The published 1.x package matches the requested package name; see the [official v1.x SDK documentation](https://github.com/modelcontextprotocol/typescript-sdk/tree/v1.x). No HTTP server or authentication flow is exposed.

Bun compiles the SDK and command modules into the same binary. No tsconfig or knip exceptions were needed. The binary remains ignored under `dist/`.

## P0 complete

The six core commands are `scan`, `rates`, `history`, `explain`, `status`, and `config`. `mcp` provides the stdio interface; `upgrade` remains installation maintenance.

The seven tools are `funding_scan`, `funding_rates`, `funding_history`, `explain`, `task_list`, `task_get`, and `config_get`. The original W5 plan and the wrap-up request say “five tools”; this delivery follows the explicit seven-tool list in the latest assignment, which adds rates and config reads. W5 stays inside `apps/cli` and the existing binary as requested.

Install paths: clone plus `./setup --host claude` or `./setup --host codex`; local Claude Code marketplace/plugin installation; standalone compiled binary; or any stdio MCP client. Generated skills live under the selected host's `~/.claude/skills/` or `~/.codex/skills/`, with the shared `mobstack/bin` shim link. The intended `lu-bann/mobstack` remote is still marked **not published yet**.

Known rough edges: a small `top` still returns the full scan payload (about 3.35 million characters in this run), which can consume substantial client context. Fee defaults and mark entry costs are estimates, not executable depth. History coverage differs across venues; Lighter has no documented keyless history. Three current symbols remained unmatched and visible. Public task reads are covered by fixtures; no populated real owner was supplied. Market data can change between requests.

No blocking questions. No P1 code, signing, keys, trading commands, remote creation, push, reference edits, or PRD edits. Stop here for Fable's review.
