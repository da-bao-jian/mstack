## Files and behavior

- `.github/workflows/release.yml` runs one Ubuntu job on a `v*` tag. It installs frozen dependencies, checks generated skills, runs check/lint/test/deadcode, checks the tag against the root and plugin versions, and extracts that version's CHANGELOG body. It builds Linux x64/arm64, macOS x64/arm64, and Windows x64, including the WalletConnect worker entrypoint. Assets are `mob-<os>-<arch>` (`.exe` on Windows), `SHA256SUMS`, and `VERSION`. The job verifies the sums, runs the Linux x64 binary, and creates the GitHub release with `gh release create --verify-tag --notes-file`.
- `install.sh` is standalone POSIX sh with `set -eu`. It downloads the latest `VERSION`, validates its stable version format, fetches the versioned binary and checksums, and checks the exact asset's SHA-256. It accepts either `shasum -a 256` or `sha256sum`. Downloads stay in a temporary directory until verification passes. The cache directory is mode 0700; installed files are mode 0755. It links `~/.local/bin/mob`, prints a PATH line when needed, and prints the home-screen, plugin, and checkout setup steps. An unrelated local command is preserved.
- `apps/cli/src/release-download.ts` uses built-in fetch, crypto, and filesystem APIs for downloaded upgrades. It verifies the latest binary before replacing a cache file or updating the local command link. `apps/cli/src/upgrade.ts` retains the existing Git checkout path: origin check, `git pull --ff-only`, frozen install, build. A checkout without origin still reports `no remote configured`.
- `scripts/release.ts` refuses tracked or untracked changes, detached HEAD, an existing tag, version downgrades, and inconsistent workspace versions. It runs all gates, updates root/workspace/plugin/marketplace versions and workspace lock metadata together, dates the Unreleased notes, and checks the changed version again. Failed checks restore the version files. Normal mode commits a new version and makes an annotated local tag; `--prepare` makes neither. An already prepared version can be tagged after its changes are committed. No mode pushes.
- `CHANGELOG.md` summarizes the 0.1 and 0.2 development lines from W0–W11 reports and records W16 under 0.3.0. Root README additions are confined to `release-start` / `release-end` markers. CHANGELOG additions have the same markers. Existing version assertions in CLI/MCP/skill tests now read the manifest so future bumps remain testable.
- `assets/logo.json` had a formatting failure at the branch base. Biome formatting was applied without changing its parsed content. No logo design or generation code changed.

## Shim decision tree

`bin/mob` forwards every argument. Plain binary resolution is quiet. Builds, downloads, and failures log to stderr. `MSTACK_VERBOSE=1` also logs the selected override, checkout, or cached binary:

1. Use executable `MSTACK_MOB_BIN`, when set. An invalid override fails explicitly.
2. Use `<root>/apps/cli/dist/mob`, when executable.
3. Read the plugin version and use executable `~/.mob/bin/mob-<version>`, when present.
4. If Bun and `<root>/apps/cli/src` exist, install frozen dependencies and build once. Build failure stops with the install options.
5. Otherwise call the standalone installer with `--version <version> --cache-only`, verify, cache, and exec.
6. On failure, print three options: install Bun and run setup; use the public curl installer; or download and verify a release manually and set `MSTACK_MOB_BIN`.

Plugin caches remain pinned to their manifest version. A standalone upgrade installs the latest version and updates the local command link; it does not rewrite a plugin manifest.

## Local release fixture

All download tests serve a shell-script binary and checksums from a loopback HTTP server. `MSTACK_RELEASE_BASE_URL=http://127.0.0.1:<port>/releases/download` selects these routes:

```text
/releases/latest/download/VERSION       -> versioned VERSION redirect
/releases/download/v<version>/VERSION
/releases/download/v<version>/mob-<os>-<arch>[.exe]
/releases/download/v<version>/SHA256SUMS
```

This matches [GitHub's latest-asset URL form](https://docs.github.com/en/repositories/releasing-projects-on-github/linking-to-releases). `VERSION` is a small extra release asset, so no GitHub API token is needed for public installs. Installer and upgrade metadata requests use the same base override. The fixture also serves `install.sh` to exercise `curl | sh` itself.

`packages/release-download.test.ts` covers override/checkout/cache/Bun precedence, first download and offline cache reuse, wrong/duplicate/missing checksums, invalid version metadata, connection failure, modes, paths with spaces, both checksum tool paths, PATH guidance, next steps, unrelated-command preservation, downloaded upgrades, and all five asset names. Existing skill tests cover the build-once path. `packages/release.test.ts` uses disposable Git repositories to check dirty-tree refusal, gate failure, version synchronization, dependency-lock preservation, notes, preparation without a tag, commit-before-tag, and tagging an already prepared version. Tests never publish a release or update a real checkout.

### Cross-compilation

Each build used [Bun's compile target](https://bun.sh/docs/bundler/executables) and both entrypoints:

```sh
for platform in linux-x64 linux-arm64 darwin-x64 darwin-arm64 windows-x64; do
  asset="mob-$platform"
  if [ "$platform" = windows-x64 ]; then asset="$asset.exe"; fi
  bun build --compile --target="bun-$platform" apps/cli/src/main.ts packages/signers/src/walletconnect-worker.ts --entry-naming '[name].[ext]' --outfile "dist/release/$asset"
done
file dist/release/mob-*
```

All five compiled. `file` identified:

| Asset | Format | Local execution |
|---|---|---|
| `mob-darwin-arm64` | Mach-O 64-bit arm64 | Version and bundled funding explanation passed |
| `mob-darwin-x64` | Mach-O 64-bit x86_64 | Version passed through Rosetta; Bun warned about AVX support |
| `mob-linux-x64` | ELF 64-bit x86-64, glibc interpreter | Not run; Docker daemon unavailable |
| `mob-linux-arm64` | ELF 64-bit ARM aarch64, glibc interpreter | Not run; no Linux arm64 runtime |
| `mob-windows-x64.exe` | PE32+ console x86-64 | Not run; no Windows runtime |

Build outputs stay in ignored `dist/` and are not committed. The release workflow runs a native Linux x64 smoke check before publication.

All five targets were rebuilt after the bump. Both macOS binaries printed `0.3.0`. Local `shasum -a 256 mob-* VERSION > SHA256SUMS` followed by `shasum -a 256 -c SHA256SUMS` passed for all six entries. `bun scripts/release.ts --notes 0.3.0` extracted exactly the four W16 bullets.

A compiled-binary upgrade smoke copied the macOS arm64 executable into a temporary home, removed Bun from PATH, and invoked `mob upgrade` against a loopback release server. It printed `Downloaded mob 0.3.1, verified SHA-256`, installed the fixture payload under `.mob/bin/mob-0.3.1`, and updated `.local/bin/mob` to that path. The temporary home was removed afterward. No live API or wallet was used.

## Publication and integration limits

- Public GitHub Release creation, asset redirects/CDN delivery, anonymous plugin downloads, and the raw-GitHub curl command remain unverified until the repository is public and a tag is pushed. No live release was created in this task.
- Native Linux arm64 and Windows execution remain unverified. Windows filesystem permissions and upgrade symlink behavior need a native check. Shell installation on Windows requires a POSIX environment; the `.exe` can also be downloaded manually.
- The existing `scripts/sign-guard.sh` exits 2 without Bun, and `hooks/hooks.json` applies it to every Claude Code Bash call. W16 verifies Bun-free standalone/shim downloads, but full Claude Code plugin use still needs Bun. Packaging that authorization guard is an integration follow-up; its behavior was not changed in this release package. README states this limit.
- Platform signatures, macOS notarization, package-manager packages, containers, and private-repository authentication are outside W16. These assets use SHA-256 checksums and HTTPS downloads.
- W12 and W15 are included through the rebase below. Their brand workspace is synchronized to 0.3.0 and their features are included in the combined CHANGELOG. W13's planned plugin-root move must also update the paths used by the shim and helper when it lands.
- No blocking specification question remains. Project tag `v0.3.0` is deliberately deferred until integration. Public installation copy is marked “after the first public release.”
