## W22.1 — runnable key import, owner casing, and verified storage

The clean headless Journey E review found that Claude Code and Codex do not
provide a secret-safe shell-variable channel. The old `$KEY` instruction made
the agent stop before import. The generated `/mob-setup` and `/mob-keys` skills
now use the accepted chat-paste trade-off directly:

```sh
printf '%s' 'mobius_…' | mob keys import --stdin --name '<name>' --venues '<a,b>' --max-size '<usd>'
```

The key is single-quoted and appears in exactly that one agent command. `printf`
is a shell builtin, so the key is not in a process list. It is never on `mob`'s
argv, in a file, environment variable, later command, or agent reply. The hook
fixture permits this exact command shape, while the CLI still refuses a key on
argv.

Both skills now stop when import reports `could not verify; not stored`. They
identify the Strategy API as unreachable. They use `--unverified` only after an
explicit user request.

Owner parsing now uses `getAddress` in the shared config parser. `mob onboard
--owner` and `mob config set owner` therefore store the same checksummed string,
and later public reads send consistent casing.

The version remains 0.4.0. No dependency changed.
