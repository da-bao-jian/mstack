# W11a — mutation skills, MCP propose tools, and sign guard

W11a only. W9 setup/binding, `/mob-setup`, `/mob-bind`, and WalletConnect remain deferred. No dependencies were added and no `bun install` ran. `wip/w8b` was not touched. No push or remote change.

## Built

- `skills-src/mob-{open,manage,close}.md.tmpl`, both host overlays, and all generated `skills/` and `skills-codex/` outputs. Open asks for market/venues, USD size, protection and assumed leverage, and auto-close. It includes the first-open risk questions from PRD §7.2. Manage stages one of six actions; close has its own path. Each shows the intent, preflight, expiry and digest, then stops. Claude offers the three specified id-bearing choices; Codex asks in prose. Only explicit browser authorization in the latest user message naming the exact id permits the agent to launch signing. The keystore path is always left to the human's terminal. Reports say “submitted, not confirmed” and point to `/mob-status`.
- The router retains its rules for secrets, untrusted data, user-supplied size, failed data, simple annualization, and maintenance. It routes mutations to the new skills and carries the sign/reject rules. Scan and status no longer claim the mutation commands are unavailable. The owner prompt uses a public `--owner` override rather than saving config without a request.
- `scripts/skill-preamble.sh` prints configured policy and signer. Normal values are `POLICY: manual|locked` and `SIGNER: keystore|browser|unset`. Config failures remain explicit. A configured but unavailable WalletConnect backend prints an unsupported-backend failure. `scripts/gen-skill-docs.ts`, `scripts/setup.ts`, and `scripts/live-skills.ts` now cover seven skills. This updates the existing installer, not the deferred `mob setup` command.
- `apps/cli/src/positions.ts` exposes the existing staging operation without CLI output. CLI rendering moved to its caller; no message, nonce, body, preflight, or signing behavior changed. `proposal-view.ts` supplies display and MCP views. The MCP view includes stored intent and results, but omits replayable signatures. An aborted MCP request is checked before staging starts.
- `apps/cli/src/mcp-tools.ts` adds `propose_open`, `propose_close`, `propose_resize`, `propose_neutralize`, `propose_protect`, `propose_auto_close`, `propose_size_mismatch_close`, `proposal_list`, and `proposal_get`. All seven propose tools share the CLI preflight and staging function. Each returns the Proposal view and the required human-signing sentence. List returns those entries; get/list do not refresh preflight. Propose tools are marked as non-idempotent local writes. There is no sign, reject, or config-set tool. The tools/list fixture and server instructions are updated.
- `hooks/hooks.json` registers `PreToolUse` for Bash with `exec bash "${CLAUDE_PLUGIN_ROOT}/scripts/sign-guard.sh"`. The Bash wrapper invokes existing Bun for JSON parsing in `sign-guard.ts`; no jq or other dependency is required. It reads stdin and the transcript, uses only the last user message's text, and checks exact id boundaries. Old approvals, assistant messages, tool-result content, missing files, malformed JSON, malformed user records, unknown dynamic ids, and missing Bun cannot authorize a sign call. Quoted ids, the resolved `$MOB` path, literal paths, supported signer flags, compound commands, and line continuations are covered. Every literal sign invocation must pass. Normal non-sign commands are allowed without a transcript. Failures exit 2 with a reason.
- Root and package manifests, plugin/marketplace versions, current header expectations, and workspace-only lockfile version entries are 0.2.0. The lockfile's dependency resolutions did not change. README documents the agent flow, human-terminal keystore requirement, MCP inputs and views, and hook limits. The custody statement is unchanged.

## Open questions and limits

1. The hook checks the presence of the exact id, as assigned. It does not infer consent from natural language. The skills require explicit authorization in addition to naming the id. The hook covers literal Bash invocations, not arbitrary shell indirection, other tools, standalone terminal commands, or a malicious host. CLI owner recovery, policy, expiry, and one-signature checks remain in force.
2. The first-open risk interview is conversation-scoped. No new persisted personal data or onboarding state was introduced. A fresh conversation does not assume a completed interview. Live Claude/Codex conversations and real wallets were not exercised; generated instructions, fixtures, the hook, MCP transport, and the CLI were tested offline.
