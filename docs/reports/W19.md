## Backend commands and storage

The env backend reads `MOBIUS_API_KEY`. It wins over every configured backend
and is read-only.

The macOS backend spawns `/usr/bin/security` directly, without a shell:

```text
/usr/bin/security add-generic-password -U -s mstack.mobius-api -a <owner-lowercase> -w <key>
/usr/bin/security find-generic-password -w -s mstack.mobius-api -a <owner-lowercase>
/usr/bin/security delete-generic-password -s mstack.mobius-api -a <owner-lowercase>
```

The create command has a brief same-user `ps` exposure because macOS requires
the password after `-w`. Only that one child process receives the secret.

The Linux backend resolves `secret-tool` from `PATH` and uses:

```text
secret-tool store --label "mstack Mobius API key" service mstack.mobius-api owner <owner-lowercase>
secret-tool lookup service mstack.mobius-api owner <owner-lowercase>
secret-tool clear service mstack.mobius-api owner <owner-lowercase>
```

`store` receives the key on stdin. It never receives the key on argv. Keychain
and Secret Service metadata uses a `0600` sidecar in the private keys directory.

The file backend writes `~/.mob/keys/<owner-lowercase>.json` as `{ key, meta }`.
It uses an exclusive `wx` temporary file, mode `0600`, and a `0700` directory.
It rejects a symlink, a non-regular file, or a wrong mode before use.

`auto` selects Keychain on Darwin. It selects Secret Service on Linux when
`secret-tool` exists. It otherwise selects the private-file backend. Import
prints the selected backend once.

## Signed key operations

W19 does not add API client routes. It stages the W18 byte contract for
`/api/keys/create|list|revoke`. The local `apiKeyMessage` copy has a named W18
parity-contract test and a replacement comment for integration.

Create reads `/api/binding/readiness` before staging and refuses an unbound
requested venue. The Proposal keeps the exact owner, name, venues, cap, nonce,
timestamp, message, and route. List states that its signature only reads.
Revoke deletes a matching local key after the server acknowledges revocation.

Live verification uses only:

```text
GET <api_base>/v1/delta-neutral/tasks?limit=1
Authorization: Bearer <key>
```

The fetch helper has no runtime dependency. W21 can replace this boundary.

## Redaction proof

The fixture secret is:

```text
mobius_01234567-89ab-cdef-0123-456789abcdef.<64 hex characters>
```

Tests run every `mob keys` action and the create-sign flow. They assert the
secret is absent from captured stdout, stderr, and Proposal JSON. A generic
Proposal test also makes both successful and failed servers echo a fixture key;
the persisted answer or error contains only
`mobius_01234567-89ab-cdef-0123-456789abcdef…`.

The static sweep scans `apps/cli/src` and `packages/keys/src`. It rejects output
or log calls that interpolate a `secret` or `.key` value.

## W19.1 — agent-mediated import

The key import direction changed before merge. An agent can now receive the key
in chat and pass it to the CLI through stdin:

```text
printf '%s' "$KEY" | mob keys import --stdin \
  --name terminal --venues hl,lighter --max-size 5000
```

`--stdin` reads all stdin, trims outer whitespace, and requires one key line. It
does not open the hidden key prompt or ask metadata questions. Missing metadata
stays absent. Without `--stdin`, the existing hidden `/dev/tty` prompt remains
available for direct human use. Import metadata can also be supplied as
`--name`, `--venues`, and `--max-size` flags.

A positional key is refused with:

```text
pass the key on stdin or type it at the prompt; never on the command line
```

`--from-env` is also refused. `MOBIUS_API_KEY` remains only a read-only runtime
override and is not an import source.

When neither stdin mode nor a controlling TTY is available, the refusal names
both alternatives without reading stdin implicitly:

```text
mob: A controlling TTY (/dev/tty) is required. Use --stdin for agent-mediated import. MOBIUS_API_KEY is only a read-only runtime override.
```

The W19.1 runtime test imports a fixture key through stdin and verifies it with
the bearer request. It then scans every file under the temporary `~/.mob`. The
full key appears only in `keys/<owner>.json`; it is absent from config, stdout,
stderr, and every Proposal path. Separate tests cover argv refusal, env-source
refusal, multiline stdin refusal, non-interactive metadata, and the unchanged
hidden-prompt path.
