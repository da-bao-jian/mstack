# W12 — brand, home screen, doctor

Built on `main`, version 0.2.0. No push. No external runtime dependency was added.

## Built

- `packages/brand`: bundled palette and immutable pixel-grid asset, half-block truecolor and xterm-256 rendering, mono/ASCII rendering, terminal detection, palette strip and style helper. Nearest xterm indices are beige 254, sky 117, orange 203 and navy 31. Six snapshots cover mono and ASCII at all sizes; color tests check every pixel pair, foreground/background codes and resets.
- `apps/cli/src/home-data.ts`, `home.ts`, `run.ts`: no-argument home, `hello`, `doctor`, all requested flags, side-by-side and narrow layouts, local Proposal summaries, and state-based next commands. Public reads start together through the existing host rate limiter. One 5,000 ms deadline aborts unfinished reads; a race also returns promptly when an injected transport ignores cancellation. Late answers cannot change the returned screen. Errors remain explicit, and malformed responses never become empty task lists or unbound credentials.
- Doctor checks configuration, owner, signer availability, policy, APIs, legal acceptance, each venue's existing readiness rules, HL perpetual account value, both Lighter account endpoints, pending/expired Proposals and cached upgrade state. It never unlocks a keystore, opens a wallet or submits a mutation. A keystore must be a regular file with mode 0600; symlinks are refused. Browser availability checks the platform opener. WalletConnect requires its configured project ID.
- `scripts/setup.ts`: after a successful non-quiet install, launches the freshly built binary's home screen, then prints `mob setup`, `mob scan --size 1000`, and `mob doctor`. Quiet installs and uninstall retain their existing behavior.
- `scripts/skill-splash.sh`, the generator, router template and both generated router skills: compact ASCII splash between `<<<MOB` and `MOB>>>`. `hello-stamp` under `MOB_HOME` (default `~/.mob`) limits it to once per hour across hosts; a directory lock covers simultaneous preambles. The router tells each host to reproduce the block exactly before other output. Other skills keep their existing preambles and authorization rules.
- Plugin description updated verbatim. `hooks/hooks.json` and `scripts/install-message.sh` add a synchronous SessionStart install notice. An atomic marker under `~/.mob` is keyed by the plugin installation path. No wallet, configuration or Proposal changes occur.
- README starts with the 44-wide mono logo. Root, CLI and brand documentation cover the screens and their limits. The custody statement is unchanged.

The [current Claude Code hook documentation](https://code.claude.com/docs/en/hooks#json-output) describes `systemMessage` as user-visible. The [SessionStart section](https://code.claude.com/docs/en/hooks#sessionstart-decision-control) accepts the common JSON output fields. These pages were fetched during this run. The synchronous hook returns `{"systemMessage":"mstack installed — type /mob to start"}` only for the first session at an installation path.

`bun install --offline` registered the internal brand workspace: “Checked 217 installs across 278 packages (no changes).” The lockfile diff contains only the workspace and its CLI link. There are no new registry packages or transitive dependencies. `assets/logo.json` remains byte-for-byte unchanged. A Biome formatter exception preserves its generator-owned formatting while keeping the root lint gate green.

## Decisions and limits

- Compact output omits the info block, retaining the logo, palette and next command. Its state reads share the same five-second budget; `--offline` omits network reads. JSON always returns the full fields. The splash may show a next signing command, but that is informational: all existing explicit-authorization rules remain unchanged.
- Upgrade status uses local `origin/main` ancestry. Home and doctor never fetch GitHub. An unavailable reference reports `not checked`; a local commit ahead of main is not an available upgrade. This source is stated in the README and doctor output.
- Doctor treats unbound venues as optional. A bound or invalid credential is critical, as are deposit/account checks for a bound venue. Config, owner, signer, API, auth, legal acceptance and readable Proposal storage are critical. Bun and upgrade notices are optional. A valid `locked` policy passes with a “mutations disabled” label. Expired Proposals are reported without making an otherwise healthy installation fail.
- The HL check establishes positive current perpetual account value, not deposit history or a spot-only balance. The brief asks for `clearinghouseState`; no extra venue endpoint was substituted.
- A pending signature is shown only after preview has passed and before expiry. Staged-but-unpreviewed Proposals are not offered as the next signing command. Home/doctor do not change Proposal state.
- An explicit non-UTF-8 locale selects ASCII; an unspecified locale retains Unicode. Explicit `--plain` and `--ascii` override detection. Palette transparency leaves the terminal background unchanged.
- No live Mobius or venue checks were needed. The smoke uses only a loopback server, and the tests inject fixture responses. Claude's rendered install notice was validated through its documented contract and script tests, not a new interactive Claude session.

Open questions for QA: confirm the doctor critical/optional policy above and the use of cached upgrade information. No W13 work was performed; an unrelated untracked `docs/prompts/W13.md` was left untouched.
