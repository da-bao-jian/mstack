  and venue-binding methods. GET calls have 30-second deadlines. POST calls have
  60-second deadlines and caller-owned idempotency keys. All calls are abortable,
  identify mstack, request JSON, and reject redirects.
- Vendored OpenAPI 1.2.0 without reformatting. Its SHA-256 is pinned as
  `70d93aa94a4def1843b4ecf638097db333c036639d66101cc7894738d548aa0e`.
  A contract test checks method, path, required headers, request properties, and
  every response code in the typed route table.
- Added response validators and named 401, 403, 409, 429, and 5xx errors.
  `Retry-After` supports integer seconds and HTTP dates. The client does not retry.
  Task command results add `disposition: "accepted, not executed"`.
- Ported `canonical` and `bindingMessage` byte-for-byte, including
  `localeCompare`. A mixed-case fixture pins current ordering. A seeded parity
  test compares 200 JSON values with a verbatim reference algorithm. The source
  file SHA-256 is pinned as
  `3a51e7538fb33c61c4e0a28feb0297c17e23b2c28aa8ac94c168625a0b942e27`.
- Added normalized prepare/read payload helpers, read headers, configurable
  binding domain, and strict sign-request classification. Venue payloads remain
  exactly as returned by the server.
- Added `apiKeyMessage`, `Secret<string>`, API-key record types, and validated
  create/list/revoke routes to `@mstack/mobius-client`. The upstream route source

- Added signed key routes to the CLI's existing fake funding server. Added the
  W18 fake Strategy API with real wallet recovery, scoped bearer grants,

- Registered the workspace in TypeScript, Knip, Bun's lockfile, and Biome. No

## Redaction proof

- `redactKey` replaces a full `mobius_<uuid>.<64hex>` value with
  `mobius_<uuid>…`.
- A table-driven test feeds the complete bearer through HTTP failures on all 11
  client routes. Neither `String(error)` nor `JSON.stringify(error)` contains it.
- Separate tests cover 401, 403, 409, 429, and 503 objects, request IDs, server
  messages/codes, transport exceptions, and malformed JSON.
- The funding client also sanitizes error messages and structured `ApiError.data`.
  A malformed key-create response cannot expose its one-time secret.
- No client or fake logs an API key.

## Fake server coverage and limits

The Strategy fake checks fixture bearers with venue and `maxSizeUsd` scopes. It
stores idempotency by owner, method, path, and key. Equal canonical bodies replay
the stored response; changed bodies return 409. Tasks move from pending to running
on read. The 429 switch returns `Retry-After: 3` once.

Binding prepare recovers the exact EIP-191 authorization. It returns two HL typed
requests, one Aster typed request, and two text requests for each Lighter target.
Submit recovers each typed or text signature. Complete venues become queued.
Reads recover wallet headers and advance queued to confirming to bound. Fixture
sets expose already-bound, rebind-required, and expiry cases.

The fake does not model PostgreSQL durability, cross-process locks, real venue or
worker calls, uncertain external confirmations, cursor semantics, the complete
production rate budget, every malformed-input branch, key hashing/active-key
limits, or funding-server readiness checks. It does not model perpetual orders;
those routes are outside W18 and are stated as such in the package README.
