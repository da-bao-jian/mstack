## Behavior and acceptance evidence

Native market strings remain unchanged on both legs and in `mobOpen`. Matching uses only the classified base. Contract multipliers normalize mark prices, not funding rates. Every null classification appears in `unmatched`; recognized duplicate `venue:market` rows and malformed numeric inputs throw.

Fees use the assigned defaults and accept per-venue overrides. The README labels defaults as estimates. Taker fees include opening and closing both legs. Builder fees include opening and closing the HL leg, doubled for either Lighter deployment. Pairs without HL have no builder fee.

Hand-computed tests cover these equal-mark examples:

| Pair | Hourly spread | Round-trip taker | Builder | Break-even |
|---|---:|---:|---:|---:|
| HL / either Lighter deployment | 0.01% | 0.09% | 0.06% | 15 hours |
| HL / Aster | 0.02% | 0.16% | 0.03% | 9.5 hours |
| Binance / Bybit | 0.03% | 0.21% | 0% | 7 hours |

Additional tests cover coin-margined OKX exclusion and opt-in, OI-capped HL flags and execution blocking, unmatched symbols, signed entry costs, missing marks, contract multipliers, HIP-3 native names, negative funding, equal rates, option overrides, qualification boundaries, failure metadata, and input immutability. Break-even tests cover nonpositive spreads, nonpositive costs, unknown costs, and invalid numbers.

Results sort by simple annualized spread and carry `observedAt`, `source`, `annualizationMethod: "simple"`, `failed`, and `unmatched`. The offline recorded snapshot produces **29 opportunities**. Only executable pairs receive a `mob open` string. The package never runs that command.

## Decisions and open questions

Fable's explicit W2 assignment takes precedence over the older build-plan wording: measured entry costs use `entryCostBasis: "mark"`; missing marks use `"unmeasured"`. The five named functions remain verbatim. The separate break-even wrapper follows the assigned percentage model and `null`/zero semantics.

One interpretation is explicit for review: a missing mark makes total entry cost unknown, so break-even is `null` and `qualifies` is false. It does not silently assume zero entry cost. Execution eligibility remains independent of qualification, as specified.

The entry-cost percentage retains the upstream helper's combined-leg-notional denominator. The helper accepts entry prices directly, preserving an interface for future book VWAP inputs. Ranking uses the supplied fee estimates; snapshots do not contain the fee-scale or referral inputs required to apply the other exported HL helpers automatically.

No blocking questions remain. W1's three questions were answered by Fable and recorded in the W1.1 report.

## W2.1 fixes

Applied D1–D5 in `fix(funding,opportunities): marks for lighter and okx, generic multipliers, binance scope`, with this report included.

- Lighter now requests funding and order-book details in parallel, joins by symbol, and includes mark prices and USD open interest. It preserves inactive listings and omits an explicit zero mark. Invalid marks or missing joins throw.
- OKX adds a third parallel request for SWAP mark prices. Every live funding instrument requires a mark.
- Classification recognizes generic power-of-ten contract prefixes across all venues, Unicode tickers, and Binance USD1 quotes. Native market strings stay unchanged. Binance excludes dated delivery contracts in its adapter.
- Pairs between Lighter deployments carry `cross-deployment` and remain executable.
- Added recorded mark fixtures, two recorded Binance dated contracts, exact expected rows, and regression tests for joins, invalid data, inactive/zero-mark behavior, classifiers, and the display flag.

The live recording included inactive MAGS and zero-mark MKR details on Lighter mainnet. Neither had a funding row, so labeled mutations of recorded funding rows test those joins. Robinhood had no inactive or zero-mark details. These limitations are documented in the fixture README.
