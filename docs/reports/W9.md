## Retained design decisions

1. **Read the HL browser chain before staging.** The existing one-shot browser bridge has a connection-only mode. It validates the expected account, returns `chainId()`, requests no signature, flushes the account response, and closes. The later Proposal pins that chain. Keystore staging uses `hl_signature_chain_id`, default `0xa4b1`, without unlocking a key. Connecting cannot authorize a signature.
2. **Polling and builder finalization belong to the approval's submit plan.** The immutable plan stores the funding-server base, status route, session id, and exact finalization body. Signing submits the venue action, polls until bound within the Proposal lifetime, then finalizes. No independent venue mutation is made by `mob bind`. Expiry or a failed status stops completion and retains the venue receipt. The HL agent step leaves builder approval for a separate Proposal when a builder is required.

The existing durable used marker, owner recovery, exact displayed payload, policy checks, and expiry checks remain active. Browser typed signing still switches to the pinned chain and never adds a chain. A known signature is never submitted again by re-entry.

## Open questions and limits

1. No live legal acceptance or binding was performed. Fake recovery proves signature/body compatibility with the ported schemas, not production account eligibility or successful venue execution.
2. Existing **standalone builder-only repair** replies are outside the new-binding steps specified in this W9 brief. The CLI fails explicitly and does not silently prepare a replacement venue key. Aster's separate `ApproveBuilder` endpoint is not added. Should a later package expose these repair ceremonies?
3. Polling stops at Proposal expiry. If the venue accepted but confirmation/finalization failed, its answer remains in the receipt. Re-entry reads server state and does not resend that signature. Automatic retries and crash recovery that resubmit signed requests are deliberately absent.
4. Upstream test files for the new ports were absent from the supplied snapshot. Tests pin original source digests, execute the captured reference HL function, and cover fixed schemas/messages plus independent fake-server recovery. No reference source was changed.
5. WalletConnect remains deferred on `wip/w8b`. This run implements only the requested keystore/browser setup choices. Referral, telemetry, session grants, and other future commands were not added.
