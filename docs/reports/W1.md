## Data and failure behavior

All adapter rows retain the canonical five funding fields and carry `observedAt`, `source`, and `annualizationMethod: "simple"`. Timestamps use Unix milliseconds. Annualization uses the unchanged upstream function: `ratePerInterval / intervalHours × 24 × 365 × 100`.

Lighter mirror rows use the target venue identifier (`binance`, `bybit`, or `hl`), `source: "lighter-mirror"`, and `sourceVenue` for the supplying deployment. Multiple observations remain separate. A mirror never clears a direct venue failure. `listed` contains unique native `venue:market` keys.

Malformed funding data fails the adapter. Hyperliquid builders are the explicit exception in the work package: each builder is isolated, contributes no rows when it fails, and reports its dex in `failed[].error`. Core failure discards all Hyperliquid rows. Builder deadlines leave time to return healthy rows before the adapter deadline.

Fixtures preserve HIP-3 names, `kPEPE`, Aster `USD1:BTC`, and all Lighter mirror exchanges. They also cover variable intervals, a delisted Hyperliquid market, a Bybit dated future, and Aster markets outside the specified scope. Capture metadata includes full-response hashes. Test expectations are static; tests never refresh fixtures or call live APIs.

## Spec questions and explicit decisions

1. **Upstream shape:** answered by Fable in W1.1. Keep the upstream module verbatim and retain `ObservedFundingRate extends Omit<FundingRate, "venue">`. Do not widen upstream.
2. **Mirror source value:** answered by Fable in W1.1. Drop Lighter mirror output entirely. The mirrors use Lighter's symbol namespace, have lower precision, and duplicate direct observations. Validate all feed exchanges but emit only Lighter rows. Remove `sourceVenue`; `source` is now `"direct" | "hosted"`.
3. **OKX intervals:** Fable approved derivation from `nextFundingTime - fundingTime`. This follows the [official OKX funding-rate documentation](https://www.okx.com/docs-v5/en/#public-data-rest-api-get-funding-rate). W1.1 includes a real four-hour CHIP fixture.

These decisions are documented without editing the PRD. None blocks this delivery.

## W1.1 fixes

Applied Fable's F1–F3 review. This report is included with the fix commit. The earlier W0/W1 reports were committed by Fable as `9b20051`.

### Changes

- OKX now makes exactly two requests: live SWAP instruments and `funding-rate?instId=ANY`. It joins by native `instId` and returns only live SWAP rows. A missing live funding row fails the adapter. The concurrency parameter, worker pool, old per-instrument fixtures, and concurrency tests were removed. `createOkxAdapter()` remains parameterless.
- Lighter validates each row's exchange, symbol, and rate, then emits only its own deployment rows. Both recorded Lighter fixtures still include competitor rows, so malformed and unknown mirror inputs remain tested.
- Removed `sourceVenue` and narrowed source types and validation to `direct | hosted`. Updated snapshot tests, expected rows, smoke output, and package/fixture documentation.
- Kept upstream bytes and the approved canonical row extension unchanged. Kept OKX's derived interval.

### Fixture evidence and limitation

Re-recorded both OKX endpoints once. The instruments response contained 500 SWAP instruments, all marked `live`. The bulk response contained 737 rows; the 237 extra rows were FUTURES rather than non-live SWAP instruments.

The trimmed fixtures contain BTC linear/inverse swaps, ETH, the four-hour CHIP swap, and one extra FUTURES funding row. No real non-live SWAP was available to record. `instruments-suspended.derived.json` changes only the recorded ETH instrument's state to `suspend`; it is explicitly labeled as derived and tests the required non-live exclusion. The original recorded files retain their observed values.
