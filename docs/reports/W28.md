# W28 — local approver, session-grant client, compact readiness

Built on `main` after W27. No runtime dependency was added. The version was not changed; the notes sit under Unreleased.

## Scope

The three items the signing audit left for later: a persistent local approver so keystore
users never switch terminals per signature, the client side of PRD 6.6 session grants, and
a bounded `mob status --readiness --json`.

## Delivered

- **`mob approver`.** Runs only in the human's own terminal (it refuses without a TTY).
  It verifies the passphrase once, caches it in memory for an idle window (30 minutes by
  default, `--idle-minutes`), and listens on `~/.mob/approver.sock` guarded by a per-run
  token in `~/.mob/approver.token` (both mode 0600, both removed on stop). Each request
  shows the Proposal or ceremony card in that terminal and asks `Sign it? [y/N]`; on `y`
  the existing keystore sign path runs inside the approver with the cached passphrase and
  the output is relayed back. The agent's `mob sign <id>` is routed to the approver
  automatically when the configured signer is `keystore`, the caller has no TTY, and an
  approver answers; `--with approver` asks for it explicitly. A declined card leaves the
  Proposal signable and sends nothing. `mob hello --json` reports `approver.running`, the
  home screen marks the signer line, the hook accepts the backend, and the skills offer
  "Sign <id> in my approver terminal" when the approver is running.
- **Session grants, client side.** `packages/mobius-client` gains byte-exact builders for
  `Authorize Mobius agent: agent=… scopes=… maxOpenNotionalUsd=… maxOpenTasks=… venues=…
  markets=… expires=… nonce=… timestamp=…` and `Revoke Mobius agent: agent=… timestamp=…`,
  with validation, plus the proposed routes `/api/agent-grants` (read),
  `/api/agent-grants/create`, and `/api/agent-grants/revoke`. `mob grant create` probes the
  read route and refuses with a clear message while the server lacks it (PRD roadmap item
  9); otherwise it generates the agent key once (a 0600 file under `~/.mob/grants/`, never
  printed), stages the owner-signed message with the grant's scope statement in the card,
  and after `mob sign` records the server's grant locally. `mob grant show` and `mob grant
  revoke <agent>` complete the set. Agent-signed mutations under a grant are not built;
  they need the server to accept `agentSignature`, and `policy auto` still covers only
  API-key submissions.
- **Compact readiness.** `withGlossary(row, { compact: true })` keeps only the fields present
  in the row and drops the cost model. Four readiness rows now total about 5 KB instead of
  42 KB; the agent reads them in one turn.

Approver tests drive a real unix socket between an agent runtime without a TTY and an
in-process approver: automatic routing with signer `keystore`, explicit `--with approver`,
one unlock per idle window, a declined card that signs nothing, a wrong token refused, and
`hello` reporting `approver.running`. Grant tests run the full create, sign, record, show,
and revoke flow against a fake server that verifies the owner's signature over the exact
message, and the clean refusal when the server lacks the routes. The readiness test pins
the compact JSON under 6 KB with a glossary limited to fields present. The QA harness was
not rerun: the approver needs a human terminal, and grants need the server.

## What did not change

The agent still never holds a wallet key or a passphrase: the approver's socket can only ask
the human, and nothing signs without the human's `y`. The exact-id rule, the fail-closed
hook, and the single-use markers stay. The grant's agent key exists only locally until the
server can accept it, and no code path signs a mutation with it yet.
