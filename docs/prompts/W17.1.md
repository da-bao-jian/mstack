**G1 (H) — the Claude preamble line does not resolve outside the checkout.** The generated Claude skills run `bash "${CLAUDE_PLUGIN_ROOT:-$HOME/.claude/skills/mstack}/bin/mob-preamble"`. Claude Code substitutes only the exact tokens `${CLAUDE_SKILL_DIR}`, `${CLAUDE_PROJECT_DIR}`, `${CLAUDE_PLUGIN_ROOT}`, `${CLAUDE_PLUGIN_DATA}` (literal textual replacement, no shell-default form), and it does not export them to the Bash tool's environment. So with the `:-` form nothing is substituted, the shell sees an unset variable, and the fallback path only exists for a `./setup --host claude` install. Observed headlessly: `bash: /Users/harryg/.claude/skills/mstack/bin/mob-preamble: No such file or directory`; the agent recovered only because its cwd happened to be the checkout. Fix: every Claude skill ships `scripts/preamble.sh` (committed, generated), which resolves its own physical directory (`CDPATH='' cd -- "$(dirname -- "$0")" && pwd -P`, so a symlinked personal-skill install resolves back into the checkout) and execs `../../../bin/mob-preamble "$@"`; the skill line becomes `bash "${CLAUDE_SKILL_DIR}/scripts/preamble.sh"` (router: `… --router`), and `allowed-tools` gains `Bash(${CLAUDE_SKILL_DIR}/scripts/preamble.sh *)`. `${CLAUDE_SKILL_DIR}` is documented as substituted for personal, project and plugin skills alike (code.claude.com/docs/en/skills, "Available string substitutions"; symlinked skill directories are supported). Codex keeps `bash ~/.agents/skills/mstack/bin/mob-preamble`. Tests: the generated Claude skills contain no `:-`, every skill has the script, the script resolves from (a) the plugin root, (b) a temp-HOME `./setup --host claude` symlink install, (c) a copied plugin cache directory; the live-skills harness runs the preamble through the script from a cwd outside the checkout.
