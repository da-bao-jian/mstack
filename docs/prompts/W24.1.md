## Layout, 80 columns, compact logo (13 rows) left, text right starting three spaces after the widest art row

```text
                  #-------------   mstack 0.4.0 · 0xA4e8…fBde
                ###-------------   ───────────────────────────
              #####-------------   Market     RSR   long hl · short bybit      837% net APY   scan 4 min ago
      +++++++-#####-------------              KAIA  long binance · short bybit  236% net APY
    +++++++++######-------------   Positions  1 running · $1,000 per leg · est. funding +$0.42/day
  +++++++++++######-------------   Ready      hl ✓  lighter ✓ · key mobius_ab12… · cap $5,000
 ++++++++++++######-------------   Policy     manual · you approve each Proposal by naming it
 -------------######+++++++++++    Next       say "open the best pair"   or   mob scan
  ------------######+++++++++
  ------------######+++++++
  ------------#####
  ------------###
  ------------#                    ■■ sky  ■■ orange  ■■ navy
```

Every row answers a question the user has when they open the tool:
- **Market** (what is worth doing right now): the top two executable pairs from the most recent scan when a cached snapshot exists and is under 15 minutes old (the funding package already caches; do not run a venue scan from the greeting, it takes tens of seconds); otherwise one line `Market     run mob scan for live funding across 7 venues`. Show base, long and short venues, net APY, and the cache age.
- **Positions** (what is at stake): from the status read the home screen already performs: `n running · $size per leg · est. funding +$x/day` using the task's funding estimate when the API provides one, otherwise omit the estimate; `none` when empty; `unreadable` when the read fails.
- **Ready** (can I trade): bound venues with `✓`, needs repair with `✗`, then the key prefix, its check result and cap. Before onboarding the row becomes `Onboarding  legal ✗ · hl – · lighter – · key none` and Next says `say "set me up"`.
- **Policy** (how the agent behaves): `manual · you approve each Proposal by naming it`, `auto · the agent may submit inside the key's caps` in orange, or `locked · reads only`.
- **Next**: one or two actions, derived from the same logic the onboarding checklist uses.
Drop the Signer, Legal, API latency and full-Owner rows; `mob doctor` keeps them. Rows past the art continue below it. Under 72 columns, or with `--stacked`, fall back to the stacked layout. The whole block, right column included, sits inside the `<<<MOB` and `MOB>>>` markers in ASCII mode. `--json` is unchanged except for a new `market` field carrying the two cached rows when present.
