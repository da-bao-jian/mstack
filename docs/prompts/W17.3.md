Fable here. CI is not deterministic: run 38164197803 (push of W17, `35294f3`) failed with exactly one test, `preamble prints configured policy and walletconnect signer` in `packages/skills.test.ts`, "timed out after 15000ms"; the next push passed. W13 and W14 each saw the same test family time out locally under load. Root cause as I read it: `preambleHome()` points PATH's `mob` at `bun --preload no-network.ts apps/cli/src/main.ts`, so every `mob` spawn transpiles the whole CLI from source (about 1,480 modules), and each case spawns it four or five times (two `config set`, then the preamble's `--version` and `config get`), with the other test files running in parallel on a two-vCPU runner. The 15-second budget measures the machine, not the code. The network is already stubbed (curl and git fixtures), so this is not a network leak.

Fix in one commit `test(skills): deterministic preamble tests` on `main`, no runtime dependency:
1. Make the preamble/subprocess tests cost-proportional and deterministic: warm Bun's transpile once in a `beforeAll` (one `mob --version` through the same fixture) or, better, run the fixtures against a prebuilt `apps/cli/dist/mob` when `MSTACK_TEST_MOB_BIN` is set, keeping the no-network guarantee (the compiled binary needs no `--preload`; assert via the curl fixture log and an `http_proxy=http://127.0.0.1:9` style sink that no real request happens). Keep the source-mode path as the default so a plain `bun test` still works without a build.
2. Give every test that spawns subprocesses an explicit, justified timeout (60 s) with a comment naming the spawn count; leave pure tests at the default.
3. CI (`.github/workflows/ci.yml`): build once before the tests and export `MSTACK_TEST_MOB_BIN=apps/cli/dist/mob`; bump `actions/checkout` to v5 to clear the Node 20 deprecation annotation; run `bun test --timeout 30000` as the root `test` script already does locally if it does not.
4. Prove it: run the full suite three times in a row locally with `bun test --timeout 30000` and once with `nice -n 19` under a parallel `bun run build` to simulate contention; all green. Append a section to docs/reports/W17.md with the timings. Do not push.
