## W3 — `apps/cli` (`mob`)

Build per docs/BUILD-PLAN.md W3 with these specifics. Zero runtime dependencies: `node:util` `parseArgs` for flags, a hand-rolled table renderer. No signing commands, no stubs for them, nothing in `--help` about them.

1. `mob scan [--size N=1000] [--market BASE] [--venues a,b] [--top N=15] [--all-pairs] [--executable] [--min-apy PCT] [--json]`. Default view: the best pair per base (first after sorting), sorted qualifying+executable first, then qualifying, then by `spreadAnnualizedPct`. `--all-pairs` shows every pair. Columns: base, long venue:market, short venue:market, spread/yr, fees (taker+builder), entry cost (or `—` when unmeasured), break-even hours, EXEC marker, flags. Footer, always printed: snapshot age, `source`, "annualized = simple, not compounded", failed venues with their error, unmatched count. `--json` prints the full `RankedOpportunities` plus a `view` array of the rows shown. Exit codes: 0 ok; 1 usage error; 2 when no venue returned rates; `--strict` makes any venue failure exit 3.

2. `mob rates [--venue V] [--market BASE] [--json]`: the raw snapshot rows (per-hour and annualized), same footer. Cheap and useful.

3. `mob history <BASE> [--days 7] [--venues a,b] [--json]` using keyless history endpoints only: HL `POST /info {type:"fundingHistory", coin, startTime}` (hourly rows `{coin, fundingRate, premium, time}`; HIP-3 coins use the dex-qualified name), Binance `GET /fapi/v1/fundingRate?symbol=&startTime=&limit=1000`, Aster `GET /fapi/v3/fundingRate?symbol=&startTime=&limit=1000` (same shape), Bybit `GET /v5/market/funding/history?category=linear&symbol=&startTime=&endTime=&limit=200`, OKX `GET /api/v5/public/funding-rate-history?instId=&limit=100` (paginate with `after`). Lighter has no documented keyless history: print `lighter: no keyless history` in the output, never silently omit. Per venue report: sample count, hours covered, average per-hour rate = Σ rate_i / Σ interval_i hours (interval-invariant: total funding over total hours), annualized (simple), min, max. Then the average spread for the best pair among the venues that have history. Resolve BASE to each venue's native market via the live snapshot's classification (so `PEPE` finds `kPEPE`, `1000PEPEUSDT`, `1000PEPE`). Put the history fetchers in `packages/funding/src/history/` with fixtures and tests, same adapter rules.
