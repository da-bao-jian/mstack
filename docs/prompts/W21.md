## 1. Proposal kind `api-submit`
- `mob open|close|resize|cancel` stage `kind: "api-submit"` when a key is stored for the owner (or `MOBIUS_API_KEY` is set) and the key's known venues cover the request; otherwise they stage today's wallet-signed Proposal and say why (`no key: run mob onboard`, or `key lacks venue aster`). The Proposal stores: route (`POST /v1/delta-neutral/tasks`, `…/{id}/close|resize|cancel`), the exact JSON body, an `idempotencyKey` (`p-N:<uuid>`, generated at staging, persisted before any send), expiry 300 s like every Proposal, and a preflight: the existing 14 client checks for open, plus `key.venues` ⊇ both legs and `sizeUsd ≤ key.maxSizeUsd` when the meta is known (when unknown, the check reads `unknown · server decides`).
- Cards show `Next: mob submit p-N` and never a signer; `mob proposals` shows kind `api`.

## 2. `mob submit <id>`
- Check order: Proposal exists → not terminal/expired → policy (`locked` refuses; `manual` and `auto` proceed; the hook decides who may run it, see 4) → key present (env or store) → send through `@mstack/mobius-api` with the Proposal's Idempotency-Key. 202 → status `submitted`, store `{ taskId, status }`, print "accepted, not executed; `mob status` shows the worker state". 409 `IdempotencyConflict` → read the current task by id when the server returns one, else print the exact server message. 429 → print `Retry-After` and stop (no loop). 401 → "key rejected; run `mob keys show`". 403 → the server message (scope or cap). A submitted Proposal cannot be submitted again (same marker discipline as `.signature-used`).
- Cancel: `POST …/{taskId}/cancel` only while the task is `pending`; close while `running`; resize body `{ longTargetBase?, shortTargetBase?, disableSizeMismatchAutoClose? }` valued server-side.
- Manage edits (`protect`, `auto-close`, `neutralize`, `size-mismatch-close`) stay wallet-signed; their cards say "not available through the API key yet (Mobius ask D); sign with your wallet".

## 3. `mob status` with the key
- When a key is present, read `GET /v1/delta-neutral/tasks` (keyset pages, `limit` 20) and `GET …/{id}`; map the API task shape to the existing grouped view (decimal strings formatted at the edge only). Without a key, keep the public read. `--json` carries `source: "api" | "hosted"`.

## 4. Policy `auto` and the guard
- `mob setup --policy auto` requires a stored key and prints a warning; the home screen shows `policy: auto · the agent may submit inside the key's caps` in the warning color while active.
- The sign-guard hook also matches `mob submit <id>`: under `manual` the latest human message must name the id (same rule as sign); under `auto` the guard allows `mob submit` for `api-submit` Proposals and still blocks `mob sign`. The policy is read from the same config the CLI uses; a missing or unreadable config blocks. Fixture transcripts for both policies, mutation-tested.
