## 1. `packages/keys` (`@mstack/keys`)
- `KeyStore` interface: `put(owner, key, meta)`, `get(owner)`, `delete(owner)`, `describe(owner)` → `{ prefix, backend, meta }` without the secret. `meta` = `{ name?, venues?, maxSizeUsd?, importedAt, verifiedAt?, apiBase }`.
- Backends, selected by `config.key_store` (`auto` default): `env` (`MOBIUS_API_KEY`, read-only, wins when set, never written), `keychain` (macOS: spawn `/usr/bin/security` directly, never through a shell, `add-generic-password -U -s mstack.mobius-api -a <owner-lowercase>`, secret passed with `-w` on the argv of that one child process — document the brief same-user `ps` exposure; `find-generic-password -w`; `delete-generic-password`), `secret-tool` (Linux, secret on stdin with `store --label`, `lookup`, `clear`), `file` (`~/.mob/keys/<owner>.json`, created `wx` 0600 in a 0700 directory, rejected if a symlink or wrong mode, JSON `{ key, meta }`). `auto` picks keychain on darwin, secret-tool on linux when the binary exists, otherwise file, and prints the chosen backend once at import. Every backend is behind the same tests with the external binaries faked on PATH.
- Key format `^mobius_[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}\.[0-9a-f]{64}$`; `prefixOf(key)` → `mobius_<uuid>…`; `redactKey(text)` for all output paths (W18 ships the same function in the client; keep this one identical and add a test that the two strings match once both land — reference it by name).

## 2. CLI commands (`mob keys …`)
- `import`: reads the key from `/dev/tty` with echo off through the existing keystore TTY reader (never stdin, argv or env); refuses when no TTY (message names `MOBIUS_API_KEY` for bots); validates the format; verifies live (200 → store; 401 → "key rejected by the API, not stored"; network error → "could not verify; not stored", with `--unverified` to store anyway, printing a warning); asks on the TTY for optional `name`, `venues` and `maxSizeUsd` (free text, validated) so the home screen can show limits; prints only the prefix and backend.
- `create --name <n> --venues a,b[,c,d] --max-size <usd>`: stages a Proposal (`kind: sign-text`, message from `apiKeyMessage("create", …)`, route `/api/keys/create`, body with `nonce`/`timestamp`), card shows name, venues, cap and the exact message. On `mob sign`, the submit answer's `key` is passed to the key store and **replaced in the stored Proposal answer by its prefix**; the card after submission says "Key mobius_ab12… stored in <backend>". Preflight: the funding server's `/api/binding/readiness` must show every requested venue bound (the server refuses otherwise with 409). Extend the Proposal `submit` with an optional `onAnswer: "store-api-key"` marker handled in the CLI's sign path.
- `list`: stages a `sign-text` read Proposal (`apiKeyMessage("list", …)`, route `/api/keys/list`); after signing, prints a table: prefix, name, venues, cap, created, revoked. Explain in the card that this signature only reads.
- `revoke <uuid>`: stages a Proposal (`apiKeyMessage("revoke", …)`); after submission, if the revoked id matches the stored key's uuid, delete it from the store and say so.
- `show`: prefix, backend, meta, and a live check `ok · 212 ms` / `rejected (401)` / `unreachable`; `--json` for agents without the secret.
- `delete`: removes the local copy only, with a reminder that the key still works until revoked.
